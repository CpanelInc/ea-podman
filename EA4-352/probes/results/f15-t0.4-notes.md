# F15 / T0.4 measurements (2026-11-06)

Run by hand on the kit layout (`eapodtest`, unit `ea-podman-web.eapodtest.01.service`). The 1.x comparison is `../f15-1x.sh`; its logs are `ea4-352-u2{2,4}/f15-1x.log`.

## Ubuntu 24.04 (podman 4.9.3): conmon SIGKILLed, unit `failed` after 3 restarts

| Command, as the account | Result | State after |
|---|---|---|
| (none) | | `stopping`, Pid and ConmonPid of the dead processes |
| `podman ps -a --sync` | | `stopping` |
| `podman stop -t 0` | prints the name | `stopping` |
| `podman kill` | `container state improper: stopped` | `stopping` |
| `podman container cleanup` | prints the name | `stopping` |
| `podman stop --ignore -t 0` | prints the name | `stopping` |
| `podman init` | `has already been created in runtime: container state improper` | `stopping` |

**Account-wide refresh:** stop all three units and the anchor, then remove `libpod/tmp/alive` and `alive.lck`. Starting the anchor then fails with `cannot re-exec process to join the existing user namespace`, because of a stale `pause.pid`. With that removed too, the anchor starts and `web` goes to `created`. Its first start fails with `crun: container … already exists`; `Restart=` brings it up and it serves (200). A plain anchor stop/start, without removing `alive`, works fine (u24, el9).

## Ubuntu 22.04 (podman 3.4.4): conmon SIGKILLed

The unit comes back `active`, but the port is refused. `systemctl restart` brings it back (200).

## Correction (T0.5)

`ea-podman upgrade` without `--force` skips the recreate when the container's image hasn't moved (`_upgrade_is_needed`, `SOURCES/util.pm:777`). So the Ubuntu 24.04 recovery is `ea-podman upgrade --force <name>`.
